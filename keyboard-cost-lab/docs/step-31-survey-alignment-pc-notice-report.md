# 31단계 설문 문구 정합성 검토와 PC 환경 안내 추가 보고서

## 1. 작업 범위

이번 단계에서는 다음 두 자료를 함께 대조했다.

- 30단계 테스트 페이지의 사용자 화면 문구
- 현재 Google 설문 응답 시트의 `문항_맵`

검토 결과, 현재 설문은 이미 `테스트`, `과업`, `조작 부담`, `화면낭독기`처럼 테스트 페이지와 같은 핵심 용어를 대부분 사용하고 있었다. 따라서 문항 전체를 다시 쓰지 않고, 실제 화면 변경과 맞지 않는 부분과 말투가 어색한 부분만 수정 대상으로 정했다.

## 2. 설문 문구 정리

### 2.1 설문 제목과 첫 안내

설문 제목을 테스트 페이지 제목과 맞춰 다음과 같이 정리한다.

- `과도한 키보드 조작 테스트 설문`

설문 첫 설명에는 다음 내용을 순서대로 넣는다.

1. 설문을 진행하는 기관과 목적
2. 설문 전에 테스트 페이지에서 세 서비스를 모두 진행해야 한다는 안내
3. 테스트 페이지 링크
4. Windows, macOS 등을 사용하는 데스크톱이나 노트북 PC에서 참여해 달라는 안내
5. 정답이 없고 경험을 그대로 답하면 된다는 안내
6. 참여가 자발적이며 중단할 수 있다는 안내
7. 답변 제출 시 설문 참여 안내를 확인하고 동의한 것으로 본다는 문장
8. 응답 이용 목적과 문의처

테스트 페이지 링크:

https://ajackpot.github.io/keyboard-cost-lab/index.html

### 2.2 서비스별 질문

대부분의 현재 문항은 그대로 유지했다. 다음 두 부분만 조정했다.

- 검색 결과 목록의 첫 질문에 현재 화면에서 실제로 사용하는 `검색어`, `정렬 기준`, `자료 범위`를 모두 반영했다.
- 서비스별 불편 사항 설명에서 `비교안 A나 B`를 반복하지 않고 `두 화면 중 어느 쪽이든`으로 바꿨다.

검색 문항:

> 검색어, 정렬 기준, 자료 범위를 적용해 원하는 자료를 찾기에는 어느 화면이 더 쉬웠습니까?

서비스별 불편 사항 공통 설명:

> 두 화면 중 어느 쪽이든 불편한 부분이 있었다면 적어 주세요. 특별히 없으면 “없음”이라고 적어 주세요.

### 2.3 테스트 마무리 질문

현재 설문에 이미 존재하는 다음 문항은 유지했다.

- 가장 많이 사용한 입력 방식
- 함께 사용한 보조기술이나 입력 방식
- 입력 방식에 얼마나 익숙한지
- 조작 부담이 가장 컸던 서비스
- 탐색하기 불편했던 부분과 바라는 개선점
- 평소 탐색하기 쉬웠던 서비스 사례

마지막 사례 문항은 긴 글 입력란에 맞게 질문형보다 요청형이 자연스러워 다음처럼 다듬었다.

> 평소 사용한 웹사이트나 앱 중 원하는 메뉴나 자료를 찾기 쉬웠던 사례와 그 이유를 적어 주세요.

## 3. PC 환경 안내

테스트는 키보드와 스위치를 사용하는 PC 환경을 전제로 하므로, 다음 문장을 세 서비스 소개 화면의 `알아두세요` 목록 첫 항목에 동일하게 추가했다.

> 이 테스트는 Windows, macOS 등을 사용하는 데스크톱이나 노트북 PC에서 진행해 주세요.

안내 위치는 다음과 같다.

- 예약 캘린더 서비스 소개
- 댓글 목록 서비스 소개
- 검색 결과 목록 서비스 소개

홈, 과업 준비, 과업 수행 페이지에는 같은 문장을 반복하지 않았다.

## 4. 기프티콘 지급 정보

### 4.1 추가 위치와 입력란

`평소 사용한 웹사이트나 앱 중 원하는 메뉴나 자료를 찾기 쉬웠던 사례와 그 이유` 문항 다음, `자동 응답 영역` 앞에 다음 영역을 추가한다.

- 섹션 제목: `기프티콘 지급 정보(선택)`
- `성명(선택)`
- `휴대전화번호(선택)`

두 입력란은 모두 필수가 아니다.

### 4.2 개인정보 안내

섹션 설명에는 다음 내용을 분리해 알린다.

- 수집·이용 주체
- 수집 항목: 성명, 휴대전화번호
- 이용 목적: 설문 참여 기프티콘 발송 및 발송 확인
- 보유·이용 기간: 지급 완료 시까지 보관하고 지급 후 지체 없이 파기
- 개인정보를 입력하면 설문 응답과 함께 저장된다는 사실
- 동의를 거부해도 테스트와 설문 참여에는 불이익이 없다는 사실
- 동의하지 않으면 두 입력란을 비워 두어야 한다는 안내
- 기프티콘을 받으려면 두 항목을 모두 입력해야 한다는 안내
- 개인정보 관련 문의처

이 버전은 요청에 따라 성명 또는 휴대전화번호를 입력하면 개인정보 수집·이용에 동의한 것으로 보는 문장을 사용한다.

다만 개인정보 보호법은 동의 사항을 구분해 정보주체가 명확하게 알 수 있도록 안내하고 동의를 받도록 정하고 있다. 개인정보보호위원회의 경품 제공 사례도 별도 동의 선택을 두고 있다. 따라서 실제 공개 전에는 기관의 개인정보 보호 담당자 또는 법률 전문가에게 `입력 시 동의 간주` 방식이 충분한지 확인하는 편이 안전하다. 별도 동의 체크 문항이나 설문 응답과 분리된 기프티콘 신청 폼을 사용하는 방식이 개인정보 결합 위험을 더 줄일 수 있다.

또한 성명과 휴대전화번호를 같은 설문에서 받으면 해당 응답은 더 이상 익명 응답이 아니다. 운영자는 기프티콘 지급 담당자만 해당 열을 볼 수 있도록 권한을 제한하고, 지급 완료 뒤 실제로 삭제했는지 확인해야 한다.

## 5. Apps Script 변경

추가한 실행 함수:

```javascript
updateKeyboardCostLabSurveyContentStep31()
```

이 함수는 다음 작업을 수행한다.

- 기존 Form과 응답 시트를 ID로 연다.
- 설문 제목, 설명, 제출 완료 메시지를 갱신한다.
- Google 계정 이메일 자동 수집을 끈다.
- 기존 24개 응답 문항의 문구와 선택지를 현재 상태로 보존·갱신한다.
- 기존 `입력 방식 익숙함` 문항을 누락하지 않고 연동 정보에 포함한다.
- 기프티콘 섹션, 성명, 휴대전화번호 입력란을 없을 때만 추가한다.
- 새 항목을 `자동 응답 영역` 바로 앞에 정렬한다.
- `문항_맵`과 `연동_JSON`을 `step-31-survey-v4`로 갱신한다.

항목 이동은 이전에 발생한 `FormApp.ParagraphTextItem, number` 시그니처 오류를 피하기 위해 모두 정수 인덱스 방식의 `form.moveItem(fromIndex, targetIndex)`를 사용한다.

## 6. 테스트 페이지 내부 설문 설정 정리

`data/survey-config.js`에는 이전 설문 전체 문항의 오래된 제목이 남아 있었지만, 웹앱이 실제로 사용하는 값은 다음뿐이었다.

- 설문 응답 URL
- 세 서비스 목록
- 자동 응답 영역의 비교안 A/B 수행 기록 6개 `entry.*` 값

따라서 설문 전체 문항 메타데이터를 중복 보관하지 않고, 수행 기록 자동 입력에 필요한 공개 정보만 남겼다. 설문 문항 전체 목록과 새 기프티콘 입력란의 `entry.*` 값은 Apps Script 실행 뒤 응답 시트의 `연동_JSON`에서 관리한다.

## 7. 검증

다음 검사를 수행했다.

- Apps Script를 `.js`로 복사한 뒤 `node --check`
- FormApp과 SpreadsheetApp 모의 객체를 사용한 실행 테스트
- 신규 항목 순서 확인: 기프티콘 섹션 → 성명 → 휴대전화번호 → 자동 응답 영역
- 같은 함수를 두 번 실행해도 신규 항목이 중복 생성되지 않는지 확인
- 기존 `입력 방식 익숙함` 문항이 연동 정보에 남는지 확인
- 테스트 페이지 사용자 화면 JavaScript 문법 검사
- `npm run check`

실제 Google Form에서 새 항목 ID와 `entry.*` 값이 만들어지는 과정은 계정 권한이 필요하므로 이 환경에서는 실행하지 못했다. Apps Script 실행 뒤 `연동_JSON`이 갱신되면 신규 항목의 실제 ID와 미리 입력 매개변수가 기록된다.
