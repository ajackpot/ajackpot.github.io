# 33단계: 완료 과업 건너뛰기와 진척률 표시

## 1. 작업 목적

서비스별 과업 기록은 브라우저 저장소에 남지만, 이전 버전에서는 사용자가 메인 창을 닫았다가 다시 들어오면 저장된 과업을 이어서 수행할 수 있는 진입 동작이 없었다. 홈 화면도 `진행 중`과 완료 개수만 보여 주어 전체 수행량 중 어디까지 왔는지 바로 알기 어려웠다.

이번 단계에서는 다음 흐름을 추가했다.

- 한 서비스에서 1개 이상, 4개 미만의 과업 수행 기록이 있으면 서비스 소개 화면에 `이전에 수행한 과업 건너뛰기`를 표시한다.
- 이 버튼을 누르면 완료한 과업을 다시 열지 않고 저장된 수행 순서에서 첫 번째 미완료 과업으로 이동한다.
- 4개를 모두 수행한 서비스에는 건너뛰기 버튼 대신 `최종 결과 화면으로 이동`을 표시한다.
- 홈 화면에는 `4개 중 N개 완료(N%)` 형식으로 진척률을 표시한다.

현재 각 서비스는 2개 과업을 두 화면에서 수행하므로 서비스 하나의 전체 수행 단위는 4개다.

## 2. 사용자 화면 동작

### 2.1 수행 기록이 없는 경우

서비스 소개 화면에는 기존과 같이 다음 두 동작을 제공한다.

- `첫 과업 준비하기`
- `다른 서비스 고르기`

재개 또는 최종 결과 버튼은 표시하지 않는다.

### 2.2 1~3개 과업을 수행한 경우

서비스 소개 화면에는 다음 순서로 동작을 제공한다.

1. `이전에 수행한 과업 건너뛰기`
2. `첫 과업부터 다시 시작`
3. `다른 서비스 고르기`

`이전에 수행한 과업 건너뛰기`를 누르면 저장된 A/B 페이지 유형 배정과 수행 순서를 복원하고, 그 순서에서 아직 기록이 없는 첫 과업의 준비 화면을 연다.

예를 들어 수행 순서가 `비교안 B → 비교안 A`이고 비교안 B의 2개 과업과 비교안 A의 첫 과업을 마쳤다면, 재개 시 비교안 A의 두 번째 과업 준비 화면으로 이동한다.

### 2.3 4개 과업을 모두 수행한 경우

서비스 소개 화면에는 다음 순서로 동작을 제공한다.

1. `최종 결과 화면으로 이동`
2. `첫 과업부터 다시 시작`
3. `다른 서비스 고르기`

최종 결과 버튼을 누르면 과업 준비 화면을 거치지 않고 저장된 A/B 수행 기록을 복원하여 최종 비교 화면을 다시 구성한다.

### 2.4 처음부터 다시 시작하는 경우

`첫 과업부터 다시 시작`을 누르면 현재 서비스의 이전 저장 기록만 삭제하고 새 A/B 배정과 수행 순서로 시작한다. 예약 캘린더를 다시 시작하더라도 댓글 목록과 검색 결과 목록의 저장 기록은 유지한다.

## 3. 홈 화면 진척률

기존의 단순 완료 개수 문구를 다음 형식으로 통일했다.

- 수행 전: `4개 중 0개 완료(0%)`
- 1개 수행: `4개 중 1개 완료(25%)`
- 2개 수행: `4개 중 2개 완료(50%)`
- 3개 수행: `4개 중 3개 완료(75%)`
- 전체 수행: `4개 중 4개 완료(100%)`

서비스 카드의 항목 이름도 `진행 내용`에서 `진척률`로 바꿨다. `수행 전`, `진행 중`, `수행 완료` 상태 표시는 별도로 유지한다.

저장 기록이 예전 버전에서 만들어져 과업 수 정보가 현재 서비스와 다르더라도, 홈 화면은 현재 서비스 정의인 `2개 과업 × 2개 화면`을 우선하여 4개를 기준으로 계산한다.

## 4. 저장 및 복원 구조

### 4.1 공통 재개 계획

`lib/experiment-store.js`에 다음 공통 처리를 추가했다.

- 완료 개수와 전체 개수로 백분율 계산
- `4개 중 N개 완료(N%)` 문구 생성
- 저장된 수행 순서에 따른 첫 미완료 과업 탐색
- 저장된 A/B 배정, 수행 순서, 과업 결과, 실행 상태를 묶은 재개 계획 생성
- 현재 서비스 기록만 삭제하는 초기화 함수

첫 미완료 과업은 단순히 비교안 A부터 찾지 않고 실제 저장된 수행 순서를 따른다. 따라서 `B → A` 순서로 시작한 테스트도 같은 순서로 이어진다.

### 4.2 실행 상태 스냅샷

과업 결과 배열만으로는 다음 과업에 필요한 서비스 상태를 모두 복원하기 어렵다. 그래서 과업 하나를 저장할 때 각 비교안의 실행 상태도 함께 저장하도록 했다.

예약 캘린더는 다음과 같은 상태를 복원한다.

- 예약 내역과 현재 예약
- 적용한 조건과 작성 중인 조건
- 상담 옵션과 알림 설정
- 현재 선택한 예약 시간

댓글 목록은 다음과 같은 상태를 복원한다.

- 댓글 조건과 현재 댓글
- 도움이 돼요 상태
- 답글 작성자 무작위 배정
- 제출한 답변과 열어 본 상세 정보

검색 결과 목록은 다음과 같은 상태를 복원한다.

- 검색어, 정렬 기준, 자료 범위
- 저장한 자료와 저장 옵션
- 미리보기 답변
- 화면별 미리보기 정답 무작위 배정

### 4.3 이전 저장 기록과의 호환

32단계 이전에 저장된 기록에는 실행 상태 스냅샷이 없다. 이런 기록도 과업 결과에 남아 있는 값을 이용해 가능한 범위에서 상태를 복원한다.

- 예약 캘린더: 마지막 과업의 예약·취소 기록
- 댓글 목록: 마지막 과업의 댓글, 답글 작성자, 도움이 돼요 기록
- 검색 결과 목록: 마지막 과업의 자료 저장 상태와 결과 메모에 남은 미리보기 정답

새로 수행한 기록부터는 전체 실행 상태 스냅샷을 사용하므로 더 정확하게 이어진다.

## 5. 서비스별 반영 파일

- `app.js`: 홈 진척률, 예약 캘린더 재개와 최종 결과 복원
- `comments-app.js`: 댓글 목록 재개와 무작위 답글 작성자 상태 복원
- `search-app.js`: 검색 결과 목록 재개와 무작위 미리보기 정답·저장 상태 복원
- `lib/experiment-store.js`: 공통 진척률 계산, 재개 계획, 저장 상태, 서비스별 초기화
- `lib/service-shell.js`: 저장 상태에 따른 공통 서비스 소개 버튼
- `scripts/check-step-33-resume-progress.mjs`: 재개·완료·진척률 회귀 검사

## 6. 자동 검사

새 회귀 검사에서는 다음을 확인한다.

- 3개 기록에서 진척률이 75%인지
- `B → A` 순서를 유지하며 정확한 다음 과업을 찾는지
- 저장된 무작위 A/B 배정표를 유지하는지
- 4개 기록에서 다음 과업 없이 완료로 판정하는지
- 수행 기록이 없을 때 재개 버튼을 숨기는지
- 부분 기록에서는 건너뛰기 버튼을, 전체 기록에서는 최종 결과 버튼을 표시하는지
- 현재 서비스 과업 수가 오래된 저장 기록의 과업 수보다 우선하는지
- 처음부터 다시 시작할 때 현재 서비스 기록을 지울 수 있는지
- 세 서비스 모두 재개 함수를 사용하고 실행 상태 스냅샷을 저장하는지
- 검색 결과 목록의 무작위 미리보기 정답 상태를 보존하는지

이 검사는 `npm run check`와 `npm run smoke`에 포함했다.

## 7. 수동 확인이 필요한 항목

자동 검사와 별도로 실제 브라우저에서 다음 흐름을 확인해야 한다.

1. 한 과업을 저장한다.
2. 메인 창을 닫는다.
3. 홈을 다시 열어 25% 진척률을 확인한다.
4. 서비스 소개 화면에서 건너뛰기 버튼을 누른다.
5. 두 번째 과업 준비 화면으로 바로 이동하는지 확인한다.
6. 다른 비교안까지 포함해 4개를 완료한다.
7. 다시 들어와 최종 결과 버튼이 표시되는지 확인한다.
8. 최종 결과의 A/B 페이지 유형, 수행 시간, 과업 결과가 처음 완료했을 때와 같은지 확인한다.

댓글 목록과 검색 결과 목록에서는 화면별 무작위 값이 재개 전후에 바뀌지 않는지도 함께 확인한다.
