# 32단계 A/B 배정·댓글 과업·방향키 탐색·설문 전달값 수정 보고서

## 1. 작업 범위

이번 단계에서는 다음 여섯 문제를 함께 수정했다.

1. 무작위 A/B 배정과 최종 결과의 페이지 유형 설명이 서로 맞지 않는 문제
2. 최종 비교 화면에서 다른 서비스로 이동하기 어려운 문제
3. 댓글 목록 과업 2의 대상 댓글이 여러 운영자 안내 댓글 중 하나로 구분되지 않는 문제
4. 댓글 목록 과업 2의 성공 판정이 불필요하게 댓글 범위 선택값에 의존하는 문제
5. 개선된 예약 시간표·댓글 목록·검색 결과 목록에서 방향키를 누를 때 위젯 이름이 반복될 수 있는 문제
6. 설문 자동 응답 기록에서 A/B의 페이지 유형과 사전 예상 시간 대비 실제 시간 차이를 알 수 없는 문제

## 2. A/B 배정 정합성

### 2.1 원인

프로젝트 내부의 `variantA`와 `variantB`는 각각 다음 의미로 사용된다.

- `variantA`: 조작 부담 문제가 있는 페이지
- `variantB`: 조작 부담이 개선된 페이지

기존 코드는 이 내부 구조 ID를 화면에 표시하는 `비교안 A`, `비교안 B`와 사실상 같은 값으로 취급했다. 수행 순서만 무작위로 바뀌는 경우에는 문제가 드러나지 않았지만, 외부 비교안 문자까지 반대로 배정하면 최종 결과가 내부 구조 ID를 기준으로 설명해 실제 A/B 배정과 어긋날 수 있었다.

### 2.2 수정

`lib/utils.js`에 다음 공통 기능을 추가했다.

- `getRandomComparisonAssignment()`
- `normalizeComparisonAssignment()`
- `getComparisonLabel()`
- `getConditionIdForComparisonLabel()`
- `getComparisonOrder()`
- `CONDITION_PAGE_TYPE_LABELS`

각 서비스 시작 시 다음 두 값은 서로 독립적으로 무작위화한다.

- 내부 페이지 수행 순서: `variantA → variantB` 또는 `variantB → variantA`
- 외부 비교안 문자 배정: `variantA=A, variantB=B` 또는 `variantA=B, variantB=A`

최종 결과에서는 비교안 A와 B를 내부 구조 ID로 다시 찾은 뒤 해당 수행값과 벤치마크를 표시한다. 따라서 다음 두 경우를 모두 정확히 처리한다.

- 비교안 A = 문제 페이지, 비교안 B = 개선 페이지
- 비교안 A = 개선 페이지, 비교안 B = 문제 페이지

서비스별 브라우저 저장 기록과 결과 파일에도 `comparisonAssignment`와 `comparisonOrder`를 함께 저장한다. 과거 저장 기록에 이 값이 없으면 기존 동작과 호환되도록 `A=variantA`, `B=variantB`로 해석한다.

## 3. 최종 화면의 다음 서비스 이동

예약 캘린더, 댓글 목록, 검색 결과 목록의 최종 비교 화면에 다음 버튼을 배치했다.

- 기본 동작: `다른 서비스 테스트 시작하기`
- 보조 동작: `이 서비스 처음부터 다시 시작`

`다른 서비스 테스트 시작하기`를 누르면 홈 화면으로 이동해 다음 서비스의 진행 상태와 시작 버튼을 확인할 수 있다.

## 4. 댓글 목록 과업 2

### 4.1 대상 구분

과업 요청을 다음처럼 구체화했다.

> 정렬 기준을 ‘도움이 많은 순’으로 바꾸세요. 3월 25일에 작성된 운영자 안내 댓글의 ‘댓글 정보 보기’를 열었다가 닫은 뒤 ‘도움이 돼요’를 누르세요.

과업 제목, 설문 서비스 과업 메타데이터, 벤치마크 과업 제목도 같은 대상 표현으로 맞췄다.

### 4.2 성공 판정

과업 2의 `requiredCategory: 'all'` 조건을 삭제했다. 이제 성공 판정에 필요한 값은 다음뿐이다.

- 정렬 기준이 `도움이 많은 순`
- 목표 댓글 ID가 `comment-admin`, 즉 3월 25일 운영자 안내 댓글
- 해당 댓글의 정보 보기를 열어 본 기록
- 해당 댓글에 도움이 돼요를 표시한 기록

따라서 댓글 범위가 `전체 댓글`이든 `운영자 안내`든 목표 댓글이 표시된 상태에서 필요한 행동을 완료하면 성공으로 판정한다. 날짜가 다른 운영자 안내 댓글에서 같은 동작을 한 경우에는 성공으로 인정하지 않는다.

## 5. 방향키 탐색 중 위젯 이름 반복 완화

### 5.1 원인

개선된 페이지의 복합 위젯은 방향키로 현재 항목을 바꿀 때 상태를 저장한 뒤 페이지 렌더 함수를 다시 호출했다. 이 과정에서 목록상자나 그리드 DOM 전체가 교체되고, 새 항목으로 초점을 다시 보냈다. 화면낭독기 입장에서는 같은 위젯 안에서 이동한 것이 아니라 위젯을 나갔다가 다시 들어온 것처럼 해석할 수 있었다.

### 5.2 수정

다음 복합 위젯에서 방향키 처리 중 전체 `render()` 호출을 제거했다.

- 예약 캘린더의 예약 가능 시간표
- 댓글 목록의 댓글 목록상자
- 검색 결과 목록의 검색 결과 목록상자

이제 방향키 이동 시 다음 값만 현재 DOM에서 갱신한다.

- 이전 항목의 `tabindex=-1`
- 다음 항목의 `tabindex=0`
- 댓글·검색 결과의 `aria-selected`
- 현재 선택 항목 CSS 상태
- 선택한 항목에 대응하는 작업 패널 내용
- 다음 항목으로의 DOM 초점

목록이나 시간표 전체가 유지되므로 최초 진입 때 위젯 이름을 알리고, 내부 방향키 이동에서는 현재 항목 정보가 중심으로 읽힐 가능성이 높아졌다.

실제 발화는 화면낭독기와 브라우저 조합에 따라 달라질 수 있으므로 다음 조합에서 수동 확인이 필요하다.

- Windows + NVDA + Chrome 또는 Edge
- Windows + JAWS + Chrome 또는 Edge
- macOS + VoiceOver + Safari

## 6. 설문 자동 응답 기록

기존 Google Form의 자동 응답 영역 6개 필드는 그대로 사용한다. 문항을 추가하거나 `entry.*` 값을 바꾸지 않았다.

각 비교안 수행 기록에는 이제 다음 정보가 들어간다.

- 비교안 문자: A 또는 B
- 페이지 유형
  - 조작 부담 문제가 있는 페이지
  - 조작 부담이 개선된 페이지
- 수행 시간, 키 입력, 초점 이동, 오선택, 다시 찾기, 완료 여부
- 키보드 사용자 예상 시간과 실제 시간의 차이
- 화면낭독기 사용자 예상 시간과 실제 시간의 차이
- 스위치 사용자 예상 시간과 실제 시간의 차이
- 과업별 수행 기록

예시는 다음과 같다.

```text
비교안: A
페이지 유형: 조작 부담이 개선된 페이지
합계: 수행 시간 50.0초, 키 입력 40회, 초점 이동 32회, 목표와 다른 선택 2회, 위치 다시 찾기 2회, 완료한 과업 2개, 완료하지 못한 과업 0개
사전 예상 시간과 실제 시간의 차이:
- 키보드 사용자: 예상 56.7초, 실제 50.0초, 예상보다 6.7초 짧게 걸림
- 화면낭독기 사용자: 예상 96.8초, 실제 50.0초, 예상보다 46.8초 짧게 걸림
- 스위치 사용자: 예상 139.8초, 실제 50.0초, 예상보다 89.8초 짧게 걸림
과업별: ...
```

과거 저장 기록에 비교안 배정표가 없으면 기존 기록의 의미를 유지하기 위해 A를 문제 페이지, B를 개선 페이지로 해석한다.

## 7. 결과 파일 보강

내려받는 JSON 결과 파일에는 다음 항목을 추가했다.

- `comparisonAssignment`
- `comparisonOrder`
- `comparisonPageTypes`
- `actualByComparison`

따라서 내부 `variantA`와 `variantB`를 알지 못해도 비교안 A와 B가 어떤 페이지 유형이었는지, 어느 실제 기록이 각 비교안에 해당하는지 확인할 수 있다.

## 8. 자동 점검

`scripts/check-step-32-regressions.mjs`를 추가하고 `npm run check`, `npm run smoke`에 포함했다. 다음 항목을 확인한다.

- 기본 배정과 역배정의 양방향 조회
- 최종 결과 코드가 현재 배정표로 A/B를 역조회하는지
- 세 서비스 최종 화면에 다음 서비스 이동 버튼이 있는지
- 댓글 과업 2의 날짜 표현과 목표 ID
- 댓글 과업 2에 불필요한 댓글 범위 조건이 없는지
- 예약 시간표 방향키 이동에서 전체 렌더가 발생하지 않는지
- 댓글·검색 결과 방향키 이동에서 목록 전체 렌더가 발생하지 않는지
- 설문 A/B 자동 입력값이 역배정과 일치하는지
- 설문 기록에 페이지 유형, 예상 시간, 실제 시간, 시간 차이가 포함되는지
- 결과 파일의 A/B 페이지 유형과 실제 기록 연결이 정확한지
- 설문 미리 입력 URL이 내부 식별값을 포함하지 않는지

벤치마크 결과 파일도 다시 생성해 현재 과업 제목과 그래프를 맞췄다.

## 9. 배포 전 남은 수동 확인

코드와 정적 검사는 완료했지만 다음 항목은 실제 브라우저와 화면낭독기에서 확인해야 한다.

1. 네 가지 조합의 A/B 배정·수행 순서가 모두 자연스럽게 진행되는지
2. 최종 결과 카드의 A/B 페이지 유형이 실제 수행 화면과 일치하는지
3. 댓글 과업 2를 `전체 댓글`과 `운영자 안내` 범위에서 각각 성공시킬 수 있는지
4. 방향키 이동 중 위젯 이름이 최초 진입 이후 항목마다 반복되지 않는지
5. 세 서비스를 완료한 뒤 열린 Google Form의 자동 응답 영역에서 A/B 페이지 유형과 예상 시간 차이가 정확히 채워지는지
