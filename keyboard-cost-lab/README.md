# 키보드 조작 부담 테스트

정적 웹앱으로 만드는 키보드·스위치 과도 조작 부담 평가용 테스트 프로젝트입니다. 서버 없이 GitHub Pages 같은 정적 호스팅에 올릴 수 있도록 HTML, CSS, JavaScript, 정적 데이터 파일만 사용합니다.

## 권장 테스트 환경

- 이 테스트는 Windows, macOS 등을 사용하는 데스크톱이나 노트북 PC 환경을 기준으로 만들었습니다.
- 휴대전화나 태블릿이 아닌 PC에서 진행합니다.
- 각 서비스 소개 화면의 `알아두세요` 영역에서 같은 내용을 한 번 안내합니다.

## 현재 구현 범위

이번 버전은 테스트 범위를 7개 서비스에서 3개 서비스로 줄이고, 실제 사용자가 과업을 수행하는 흐름에 더 가깝게 정리한 상태입니다.

- 홈 화면에서 서비스 유형을 먼저 선택합니다.
- 현재 테스트 서비스는 `예약 캘린더`, `댓글 목록`, `검색 결과 목록` 3개이며, 각 서비스는 2개 과업으로 구성됩니다.
- 홈 화면의 서비스 카드에는 반복 안내 문구 대신 서비스별 진행 상태가 `수행 전`, `진행 중`, `수행 완료`로 표시됩니다.
- 홈 화면의 각 서비스 카드에는 두 화면의 2개 과업을 합친 전체 4개 수행 단위를 기준으로 `4개 중 N개 완료(N%)` 형식의 진척률을 표시합니다.
- 홈 화면의 설문 연결 영역은 기록이 없으면 `테스트 준비`, 일부 과업이 저장되면 `테스트 진행 중`, 세 서비스를 모두 마치면 `테스트 완료`로 표시합니다. 완료 전에는 `테스트 마무리`처럼 이미 끝난 것으로 오해할 수 있는 문구를 사용하지 않습니다.
- 저장된 과업이 1개 이상 있으면 서비스 소개 화면에서 `이전에 수행한 과업 건너뛰기`를 선택해 저장 당시의 A/B 배정과 수행 순서를 유지한 채 다음 미완료 과업부터 이어갈 수 있습니다. 4개를 모두 마쳤다면 같은 위치에 `최종 결과 화면으로 이동` 버튼이 표시됩니다.
- 서비스 카드 버튼은 `예약 캘린더 테스트 시작`처럼 서비스 이름과 동작을 함께 표시합니다.
- 조작 부담 문제가 있는 페이지와 조작 부담이 개선된 페이지 중 어느 쪽이 비교안 A 또는 B가 될지 무작위로 정합니다. 수행 순서도 별도로 섞어 `A → B` 또는 `B → A` 중 하나가 됩니다.
- 과업 수행 중에는 페이지 유형을 내부 구조 ID로 판단하고, 최종 결과·결과 파일·설문 전달값에서는 실제 A/B 배정표를 기준으로 다시 연결합니다.
- 각 서비스에서 두 화면을 모두 수행한 뒤에만 최종 결과를 한 번에 표시합니다.
- 과업 준비 화면은 요청 내용과 필수 진행 방법만 보여 주고, 사전 예상 시간이나 개선 목표는 보여 주지 않습니다.
- 내부 테스트 번호와 실행 ID는 결과 저장과 탭 간 연결에만 사용하고 화면에는 노출하지 않습니다.
- 과업 준비 화면의 `과업 요청을 수행 페이지에도 표시` 스위치를 켜면 과업 수행 페이지 맨 위에도 이번 요청이 표시됩니다. 기본값은 꺼짐입니다.
- 과업 수행 페이지는 실제 서비스 화면처럼 보이도록 검색, 알림, 보관, 안내 같은 보조 기능을 노출합니다.
- 예약 캘린더의 간단한 보조 기능은 점검 중 안내 대신 화면 안 패널, 상태 변경, 조건 입력, 안내 표처럼 실제 기능에 가깝게 반응합니다. 전체 메뉴는 기본 접힘 상태이며, 조작 부담 문제가 있는 페이지에서는 숨김 메뉴가 여전히 초점 이동 대상이 되는 불편을 보여 줍니다.
- 예약 캘린더 첫 과업은 상담 주제와 알림 방법을 고르고 사전 작성란을 비워 둔 뒤, 최종 예약 확인을 거쳐 예약하는 흐름입니다. 예약 시간 확인과 최종 예약 확인 대화상자에는 실제 서비스처럼 `공유하기`도 제공합니다. 두 번째 과업은 기존 예약 취소 뒤 새 예약을 진행하는 흐름입니다. 한 주 최대 예약 2개 제한도 함께 반영했습니다.
- 구현 범위가 큰 기능만 `현재 준비 중`이라고 알리고, 페이지 밖으로 벗어나지 않게 처리합니다.
- 과업은 자동 종료되지 않습니다. 사용자가 과업 수행 페이지 하단의 `과업 종료` 버튼을 눌러야 해당 과업 기록이 저장됩니다.
- `과업 종료` 버튼을 누르면 먼저 종료 확인 대화상자가 열립니다. 이 대화상자는 종료 여부만 묻고 성공·실패 결과를 미리 알려 주지 않습니다.
- 종료 확인에서 `아니요, 계속합니다`를 누르면 과업 수행으로 돌아가고, `예, 종료합니다`를 누르면 현재 상태로 기록합니다.
- 수행 중에는 성공·실패를 암시하는 힌트나 정답 판정 메시지를 보여 주지 않습니다. 최종 과업 결과는 `예, 종료합니다`를 누른 뒤 기록 저장 대화상자에서만 표시됩니다.
- 목표 과업을 실제로 완료했더라도 자동으로 끝나지 않습니다. 예약 완료 화면, 답글 목록 확인, 도움이 돼요 토스트, 자료 저장·열기 토스트처럼 실제 서비스 피드백을 확인한 뒤 `과업 종료` 버튼을 눌러 기록합니다.
- 과업 수행 페이지의 첫 조작부터 기록을 시작하고, 수행 페이지가 보이지 않았던 시간과 하단 보조 버튼 조작은 결과 지표에서 제외합니다.
- 서비스별 과업 기록과 재개에 필요한 화면 상태는 브라우저 저장소에 보존됩니다. 중단 뒤 다시 들어오면 완료한 과업은 건너뛰고 다음 미완료 과업부터 이어갈 수 있으며, 댓글 작성자·검색 미리보기 정답처럼 화면별로 무작위 배정된 값도 가능한 한 그대로 복원합니다.
- `첫 과업부터 다시 시작`을 선택하면 다른 서비스의 기록은 유지하고 현재 서비스의 이전 기록만 지운 뒤 새 A/B 배정으로 시작합니다.
- 세 서비스를 모두 마치면 수행 기록을 설문에 자동 입력할 수 있으며, 결과 파일에도 전체 서비스 저장값을 포함합니다.
- 공통 메시지 연결, 시작 정보 저장, 결과 내보내기, 최종 비교 요약, 서비스 목록, 벤치마크 생성 목록은 공통 모듈과 데이터 파일로 관리합니다.

## 서비스 유형

- `예약 캘린더`: 날짜·상담사·상담 방식 조건을 맞추고, 일부 예약에서 상담 주제·사전 작성란·알림 방법을 선택하거나 기존 예약을 취소한 뒤 새 예약을 진행하는 과업
- `댓글 목록`: 두 비교안 모두 페이지 맨 앞의 `본문 바로가기` 링크로 글로벌 메뉴를 건너뛰고 정렬과 범위 선택부터 시작할 수 있습니다. 조건을 바꿔 댓글을 좁힌 뒤 답글 작성자를 확인하거나, `3월 25일에 작성된 운영자 안내 댓글`의 댓글 정보 보기를 열고 닫은 뒤 도움이 돼요를 남기는 과업입니다. 두 번째 과업은 댓글 범위 선택과 관계없이 지정된 댓글에서 필요한 동작을 마치면 완료로 판정합니다. 답글 내용은 고정하되 답글 작성자 이름과 정답 선택지는 과업 수행 페이지마다 무작위로 배정합니다.
- `검색 결과 목록`: 정렬 기준, 자료 범위, 검색어를 검색 조건 선택 영역에서 맞춘 뒤 미리보기 내용에 답하거나, 자료를 저장 위치와 포함할 내용 선택과 함께 보관하는 과업. `예약 변경 안내` 미리보기의 숫자 답변은 수행 화면별로 무작위 배정되고, 미리보기 본문과 답변 선택지가 같은 값으로 연동됩니다. 검색어 입력란은 기본값 없이 시작하며, 조건 적용을 누르면 입력한 검색어로 자료 목록이 다시 걸러집니다. 저장과 바로 열기는 토스트 알림으로 처리하고, 미리보기 닫기는 원래 흐름으로 돌아옵니다. 자료실 홈, 검색 도움말, 최근 검색, 보관함, 자료 요청, 이용 안내, 문의, 검색 알림 같은 보조 기능은 화면 안 패널과 상태 변경으로 반응합니다.

## 수행 기록 규칙

- 수행 기록은 과업 수행 페이지에서 처음 키를 누르거나 화면을 클릭할 때 시작합니다.
- 수행 페이지가 보이지 않는 시간은 수행 시간에 포함하지 않습니다.
- 과업 수행 페이지 맨 아래의 `예약 가능 시간으로 이동`, `댓글 목록으로 이동`, `검색 결과로 이동`, `과업 종료` 조작은 결과 지표에 포함하지 않습니다.
- 과업 종료 확인 창과 기록 저장 창의 조작도 결과 지표에 포함하지 않습니다.
- 과업 준비 화면에서 과업 설명을 읽는 시간은 기록하지 않습니다.
- 요청한 동작을 끝내지 못한 상태로 종료하면 `완료하지 못한 과업`으로 집계합니다.
- 두 화면을 모두 수행한 뒤 최종 화면에서 실제 A/B 배정, 각 비교안의 페이지 유형, 수행 기록, 사전 예상 시간, 실제 시간과 예상 시간의 차이를 함께 확인합니다.
- 댓글 답글 작성자 이름은 수행 화면별로 무작위 배정되며, 하단 답변 선택지는 해당 화면에 표시된 이름을 기준으로 생성됩니다.
- 검색 결과 목록의 미리보기 질문 정답도 수행 화면별로 무작위 배정되며, 하단 답변 선택지는 해당 화면의 미리보기 본문 값을 기준으로 생성됩니다.
- 검색 결과 목록의 간단한 보조 기능은 화면 안 패널, 토스트, 상태 변경으로 반응합니다. 조작 부담이 개선된 페이지에는 `검색 결과 영역으로 바로가기`, `검색 조건 설정으로 바로가기` 링크가 있어 단일 페이지 안에서도 주요 영역 건너뛰기를 확인할 수 있습니다.
- 댓글 목록의 `본문 바로가기`는 문제 페이지와 개선 페이지에 동일하게 제공하고, 가상 벤치마크에서도 두 페이지 모두 글로벌 메뉴 탐색 비용을 제외합니다. 이에 따라 댓글 반복 항목과 복귀 구조에서 생기는 차이를 중심으로 비교합니다.
- 조작 부담이 개선된 예약 시간표·댓글 목록·검색 결과 목록은 방향키 이동 때 위젯 전체를 다시 만들지 않습니다. 같은 위젯 안에서 현재 항목의 선택 상태와 `tabindex`만 바꾸고 초점을 옮겨, 목록이나 시간표 이름이 항목마다 반복될 가능성을 줄였습니다.
- 댓글과 검색 결과 데이터는 목표 항목이 조건 적용 직후 첫 항목으로 바로 고정되지 않도록 누적해 두었습니다.

## 실행

```bash
cd keyboard-cost-lab
node scripts/run-benchmark.mjs
npm run check
python -m http.server 4173
```

그 다음 브라우저에서 `http://localhost:4173`를 열고, 홈 화면에서 원하는 서비스 유형을 고릅니다.

## 주요 파일

- `index.html`: 홈 화면과 예약 캘린더 테스트 진입점
- `app.js`: 예약 캘린더 테스트 흐름과 홈 화면
- `comments.html`: 댓글 목록 테스트 진입점
- `comments-app.js`: 댓글 목록 테스트 흐름
- `search.html`: 검색 결과 목록 테스트 진입점
- `search-app.js`: 검색 결과 목록 테스트 흐름
- `styles.css`: 공통 화면 스타일
- `data/`: 시나리오, 과업, 사전 계산 그래프, 사전 계산 결과, 서비스 목록, 공통 측정 규칙
- `data/service-registry.js`: 홈 화면 서비스 목록과 공개 상태
- `data/benchmark-manifest.js`: 벤치마크 생성 대상과 출력 파일 목록
- `data/measurement-rules.js`: 공통 수행 기록 규칙
- `lib/benchmark-engine.js`: 사전 계산 엔진
- `lib/logger.js`: 수행 기록 수집기
- `lib/experiment-bridge.js`: 메인 창·과업 수행 페이지 메시지 연결, 시작 정보 저장, 초점 가두기
- `lib/service-shell.js`: 공통 비교 요약, 결과 내보내기, 설문 링크 생성
- `lib/experiment-store.js`: 서비스별 진행 상태, 진척률, 수행 기록, 재개 계획과 실행 상태를 브라우저 저장소에 보존
- `lib/utils.js`: 공통 유틸리티와 과업 수행 페이지 하단/완료/과업 종료 확인 대화상자 렌더링
- `scripts/run-benchmark.mjs`: 서비스별 사전 계산 결과 생성 스크립트

## 설문지 연동

- `data/survey-config.js`: Google 설문지 응답 URL과 수행 기록 자동 입력에 필요한 6개 `entry.*` 값만 관리합니다. 설문 문항 전체 목록은 Apps Script 실행 뒤 응답 시트의 `연동_JSON`에서 관리합니다.
- `lib/survey-link.js`: 3개 서비스의 수행 기록이 모두 저장되었는지 확인하고, 각 비교안의 실제 페이지 유형과 사용자 유형별 사전 예상 시간·실제 시간·시간 차이를 포함한 수행 기록 문장을 만들어 설문지 URL에 붙입니다.
- 홈 화면과 각 서비스 최종 결과 화면의 `설문 작성하기(새 탭)` 링크는 위 두 파일을 기준으로 생성됩니다.
- `scripts/google-form-step-31-update.gs`: 기존 설문 제목·설명·문항 문구를 최신 테스트 페이지와 맞추고, PC 환경 안내와 기프티콘 지급 정보용 선택 입력란을 추가합니다.
